# CRM Tasks Implementation Plan (plan 3 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HubSpot-style tasks as the core of follow-up, with a "Taken" page, tasks per deal/company/contact, and a "Vandaag" overview on the dashboard. Buitenbeleving's "Open actie" notes are converted into real tasks.

**Architecture:**
- **One new table, `crm_tasks`,** with the same safety net as the other CRM tables: RLS by organisation, change history, trash (soft delete, joining a parent's trash batch), and the self-verifying migration pattern.
- **Pure task logic** (grouping, sorting, labels) lives in `src/lib/tasks.ts`.
- **The UI reuses the Glass A components** from plan 2.

**Tech Stack:** Postgres (Supabase), plpgsql, React 18 + TanStack Query, vitest, the Docker DB harness `supabase/tests/crm_foundation/run.sh`.

**Spec:** `docs/superpowers/specs/2026-11-04-crm-productisering-design.md`, goal 4 (tasks) and goal 9 (data safety).

## Review Focus

1. **Trashing a deal or company** also trashes its open tasks in the same batch. Restore brings them back, and purge refuses while live tasks hang off the batch.
2. **A task's due date is a plain date (no timezone shift).** "Vandaag" and "Achterstallig" are computed from the user's local date, so a task due today never shows as overdue at 23:30 or 00:30.
3. **Completing a task** sets `completed_at`/`completed_by`. Reopening clears both. History shows it as "Taak afgerond" / "Taak heropend".
4. **The group view ("Algemeen")** shows no task-writing UI, and nothing errors.
5. **A task linked to a deal in another org** is rejected, as is a deal/company/contact that is in the trash.

### Task 1: `crm_tasks` table with full safety net

**Files:** Create `supabase/migrations/20261105000001_crm_tasks.sql`. Modify `supabase/tests/crm_foundation/{fixtures.sql,checks.sql}`, plus `run.sh` only if needed.

**Interfaces — produces:**
- **Table `crm_tasks`:**
  - `id uuid pk default gen_random_uuid()`
  - `org_id uuid not null → organizations on delete cascade`
  - `title text not null check (length(trim(title)) > 0)`
  - `notes text`
  - `type text not null default 'todo' check in ('call','email','todo')`
  - `priority text not null default 'medium' check in ('high','medium','low')`
  - `status text not null default 'open' check in ('open','in_progress','waiting','done','cancelled')`
  - `due_date date`, `due_time time`
  - `owner_id uuid → auth.users`
  - `deal_id uuid → deals on delete set null`, `company_id uuid → companies on delete set null`, `contact_id uuid → contacts on delete set null`
  - `completed_at timestamptz`, `completed_by uuid`
  - `created_by uuid default auth.uid()`, `created_at timestamptz default now()`, `updated_at timestamptz default now()`
  - `deleted_at timestamptz`, `deleted_by uuid`, `delete_batch uuid`
- **Indexes:**
  - `(org_id, status, due_date)`
  - `(owner_id, status, due_date)`
  - `(deal_id)`, `(company_id)`, `(contact_id)`
- **Triggers:**
  - the `updated_at` trigger;
  - `crm_tasks_completion` (BEFORE INSERT/UPDATE OF status): moving into 'done' sets `completed_at = coalesce(completed_at, now())` and `completed_by = coalesce(completed_by, auth.uid())`; any other status clears both;
  - `crm_tasks_links_guard` (BEFORE INSERT/UPDATE): each linked deal, company or contact must exist, have `org_id = NEW.org_id` (else raise 'Gekoppeld item hoort niet bij deze organisatie') and not be trashed (else raise 'Dit item staat in de prullenbak');
  - the history capture trigger;
  - the soft-delete trigger.
- **RLS:** the same 4 policies as the other trash tables (select hides trashed rows; insert, update and delete for org members).
- **Extended functions:**
  - The soft-delete cascade: deal → its tasks, and company → its tasks, both in the same batch.
  - `crm_trash_list`: tasks as their own entity `'crm_tasks'` (label = title), and `batch_counts` includes `crm_tasks`.
  - `crm_restore`: restores tasks in the batch, after their parents.
  - `crm_purge`: refuses while a live task hangs off the batch; scrubs task history.
  - `crm_integrity_counts`: gains the key `crm_tasks` (count of all rows). The before/after comparison ignores keys that are new in this migration.

### Task 2: Task logic and hooks

**Files:** Create `src/lib/tasks.ts` (+ test) and `src/hooks/useTasks.ts` (+ test). Modify `src/lib/crmTypes.ts`.

**Interfaces — produces:**
- **Types:** `Task`; `TaskStatus`, `TaskType`, `TaskPriority`, and the Dutch label maps `TASK_STATUS_LABEL`, `TASK_TYPE_LABEL`, `TASK_PRIORITY_LABEL`.
- **`taskBucket(task, today: string /* yyyy-mm-dd local */): 'overdue'|'today'|'upcoming'|'nodate'|'closed'`**
  - done or cancelled → closed;
  - no due date → nodate;
  - due < today → overdue;
  - due = today → today;
  - otherwise upcoming.
- **`localToday(now = new Date()): string`** uses local time, not UTC.
- **`sortTasks(tasks)`:** by bucket order (overdue, today, upcoming, nodate, closed), then due_date ascending, then priority (high first), then created_at.
- **Hooks:**
  - `useTasks(filter: { ownerId?: string; dealId?: string; companyId?: string; contactId?: string; includeClosed?: boolean })` covers the current org; it's disabled in the group view. It selects `*`, `deal:deals(title)`, `company:companies(name)` and `contact:contacts(name)`. That's a single FK each, so no embed ambiguity.
  - `useCreateTask()` (`org_id` from `useOrgId`), `useUpdateTask()`, `useDeleteTask()` (soft; toast "Taak verplaatst naar prullenbak").
  - `useMyOpenTaskCount()`: count of my overdue+today open tasks, using a head/count query.
